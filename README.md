# STB Channel Loop — NOC Display

Python script for Raspberry Pi that continuously cycles through channels
on an Android TV Box via ADB over USB, for permanent display on a NOC screen.

---

## Requirements

- Raspberry Pi running Raspberry Pi OS (Bookworm or Bullseye)
- Python 3 (included by default)
- Android TV Box with ADB debugging enabled
- Data-capable USB cable (not charge-only)

---

## Quick Install

```bash
git clone https://github.com/filipefsilva/stb-loop.git
cd stb-loop
sudo ./setup.sh
```

The interactive installer will ask you:

| Question | Default |
|---|---|
| Zap interval | 20 seconds |
| App package name | (optional) |
| App activity name | (optional) |

It then installs dependencies, configures the service, and guides you through
USB debugging authorization on the Android TV.

**On Pi Zero / Zero 2 W:** a reboot is required after `setup.sh` (the installer
auto-configures the dwc2 USB OTG overlay and tells you).

---

## What the Installer Does

1. Configures USB OTG overlay on Pi Zero (2) W
2. Creates system user `stb-loop`
3. Installs `adb`, `python3`, `pip`
4. Asks for looptime, app package/activity
5. Copies `loop.py` to `/opt/stb-loop/`
6. Generates a shared ADB key in `/opt/stb-loop/.android/`
7. Creates and enables `stb-loop.service`
8. Guides you through ADB authorization on the TV

The service starts automatically on every boot.

---

## After Installation

No manual steps needed — the service is already running:

```bash
# Live logs (zapping, reconnects, etc.)
journalctl -u stb-loop.service -f

# Service status
sudo systemctl status stb-loop.service

# Restart
sudo systemctl restart stb-loop.service
```

To change settings later:

```bash
sudo python3 /opt/stb-loop/loop.py --stb
sudo systemctl restart stb-loop.service
```

## Enable ADB Debugging on the STB

1. Go to **Settings → About device**
2. Tap **Build number** 7 times to enable developer options
3. Go to **Settings → Developer options**
4. Enable **USB Debugging**
5. Connect the USB cable between the Pi and the STB

> **Note:** Some devices (e.g. Xiaomi, NVIDIA Shield) have these options in
> slightly different menus. Search for "ADB" in Settings.

---

## USB Debugging Authorization

The installer uses a shared ADB key in `/opt/stb-loop/.android/` — both `root`
(installer) and `stb-loop` (service) use the same key.

During installation, you'll see an "Allow USB debugging?" popup on the TV.
Check **"Always allow from this computer"** and tap **Allow**.

**If the popup doesn't appear:**
1. TV Settings → Developer Options → **"Revoke USB debugging authorizations"**
2. Unplug and replug the USB cable
3. Run: `sudo -u stb-loop HOME=/opt/stb-loop ADB_VENDOR_KEYS=/opt/stb-loop/.android adb devices`

The service waits indefinitely — once authorized, it connects and starts zapping
automatically.

## Configuration File

Generated by `setup.sh` at `/opt/stb-loop/config.json`:

```json
{
  "app_package": "tv.perception.android.tvcabostp",
  "app_activity": "tv.perception.android.waterloo.WaterlooActivity",
  "reconnect_on_fail": true,
  "reconnect_max_retries": 0,
  "reconnect_retry_delay": 1
}
```

| Field | Default | Description |
|---|---|---|
| `app_package` | `""` | Android package to launch before zapping |
| `app_activity` | `""` | Activity class (required for Android TV) |
| `reconnect_on_fail` | `true` | Auto-reconnect if ADB drops |
| `reconnect_max_retries` | `0` | Max reconnection attempts (`0` = infinite) |
| `reconnect_retry_delay` | `1` | Seconds between reconnection attempts |

## Service File

```ini
[Unit]
Description=STB Channel Loop — NOC Display
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=stb-loop
WorkingDirectory=/opt/stb-loop
Environment=HOME=/opt/stb-loop
Environment=ADB_VENDOR_KEYS=/opt/stb-loop/.android
ExecStart=/usr/bin/python3 /opt/stb-loop/loop.py --looptime 20
Restart=on-failure
RestartSec=10
StandardOutput=journal
StandardError=journal

NoNewPrivileges=yes
PrivateTmp=yes
ProtectSystem=strict
ProtectHome=yes
ReadWritePaths=/opt/stb-loop
ReadOnlyPaths=/usr/bin/adb

[Install]
WantedBy=multi-user.target
```

## Troubleshooting

**Device not detected:**
1. **Cable:** must be data-capable (not charge-only)
2. **Port:** on Pi Zero (2) W, use the inner micro-USB port ("USB"), not "PWR"
3. **USB Debugging:** must be enabled in Developer Options on the TV
4. **Pi Zero (2) W:** `dwc2` must be in `config.txt`. Run `sudo ./setup.sh` to auto-configure
5. **Udev rules** (if `lsusb` shows device but `adb devices` doesn't):
   ```bash
   echo 'SUBSYSTEM=="usb", ATTR{idVendor}=="18d1", MODE="0666"' | sudo tee /etc/udev/rules.d/51-android.rules
   sudo udevadm control --reload-rules && sudo udevadm trigger
   ```

**Device shows `unauthorized`:**
→ Revoke authorizations on the TV (Developer Options), replug cable, run:
  ```bash
  sudo -u stb-loop HOME=/opt/stb-loop ADB_VENDOR_KEYS=/opt/stb-loop/.android adb devices
  ```

**Service won't start:**
→ `journalctl -u stb-loop.service -f`. Make sure `config.json` exists in `/opt/stb-loop/`.

**Script connects but channel doesn't change:**
→ Make sure the STB is running a live TV app that supports `KEYCODE_CHANNEL_UP`.
